## 第二部分：面向二开的重构路线

总原则（从上轮路线图继承，针对你的情况压缩）：

1. **每次只动一个边界**，改完能跑、能对比，再动下一个；
2. **先让错误能被看见**（入口收口），再谈优雅；
3. 二开新功能**永远落在扩展点上**（见 §4），不落在旧层。

### Phase 0：让执行路径可预测（1-2 天，全是小改）

这是性价比最高的一步，做完之后你才有资格验证后面所有重构。

| 步骤 | 改什么 | 验证 |
|---|---|---|
| 0.1 | 删掉三处 try/except ImportError fallback：`tradingagents/__main__.py:46-51`、`cli/main_menu.py:99-108、113-121`，直接 import 新层，报错就让它报错 | 故意在 `cli/analyze/app.py` 里写个错 import，确认程序炸出 traceback 而不是静默跑旧代码 |
| 0.2 | `pyproject.toml:36` 改为 `tradingagents = "tradingagents.__main__:app"`，让安装命令进新统一 CLI | `pip install -e .` 后敲 `tradingagents --version` 走新 CLI |
| 0.3 | 统一版本号：删掉 `__init__.py:12` 和 `__main__.py:21` 的手写 `2.0.0`，改用 `importlib.metadata.version("tradingagents")` 读 pyproject | `python -m tradingagents --version` 与 pyproject 一致 |
| 0.4 | 清掉 run_impl 的 6 处 DEBUG print 和 interface.py 死代码段（上面 C 类） | 跑一次 analyze，终端无 `[DEBUG] Step` |
| 0.5 | 重建 `tests/`，先只放 3 个冒烟测试：①`import tradingagents` 无输出无退出；②`import cli.main` 不退出；③`--version` 与元数据一致 | `pytest -q` 绿 |

### Phase 1：新旧 CLI 收口（约 1 周，分 3 个小步）

目标：让 `cli/analyze/` 成为唯一 Analyzer 入口，然后你亲手删掉旧层。

1. **断奶**：把 `fetch_announcements`/`display_announcements` 从旧 `commands/analyze/utils.py` 搬进 `cli/`（改掉 `cli/analyze/app.py:65` 的反向 import）；`cli/main_menu.py`、`cli/__init__.py` 的旧层引用按 0.1 的方式改直连新层。
2. **合并分叉**：四对分叉文件（config/models/stats_handler/utils）逐对 diff，以新层为基准吸收旧层仍被引用的部分，旧层文件改成 `from cli.xxx import *` 的薄转发（≤3 行）。
3. **删旧**：跑通 `python -m tradingagents analyze` 和主菜单两条路径后，你删掉 `tradingagents/commands/analyze/`、`tradingagents/screener/cli/`、`cli/main.py`。同时删 `commands/report/`（HTML 查看器未实现，留着是假入口，见 `ui/summary.py:254` 的 TODO）或在 Phase 1 里明确实现它——二选一，别留悬空状态。

**验收**：全仓 grep `tradingagents.commands` 和 `tradingagents.screener.cli`，结果为 0。

### Phase 2：统一图执行驱动（约 1 周）

目标：三个驱动器变一个，UI 不再读图内部。

1. 在 `TradingAgentsGraph` 上加一个公开方法（比如 `stream_events(state)`），把 run_impl 里的裸流循环搬进去，Dashboard 通过回调/事件消费；
2. `cli/analyze/run_impl.py` 退化为：构造 request → 调用图 → 把事件喂给 Dashboard → 包装 result。删掉对 `graph.graph`、`graph.propagator`、`_synchronize_structured_state` 的所有直接触碰；
3. 旧 `propagate()` 保留（main.py / deep_analyzer 还在用），但它和 stream 路径共享同一个内部执行函数。

**验收**：`grep -n "graph\.\(graph\|propagator\|_synchronize\)" cli/` 为 0；无 UI 的情况下能跑完一次分析（写成第 4 个冒烟测试，用 mock LLM）。

### Phase 3：状态与配置收口（1-2 周，二开前必须完成的最低限度）

不求彻底消灭双写，只求**确立权威**：

1. 在 `agent_states.py` 顶部用注释+常量声明：结构化字段（`analyst_reports`/`debate_blocks`/`decision_blocks`/`ticker_info`）是 canonical，平铺字段是 legacy 只读兼容；
2. `_synchronize_structured_state` 改名 `_legacy_compat_sync` 并加 Deprecation 警告，方向反转的覆盖逻辑记入待办（哪个版本停止写平铺字段）；
3. 把 `state_helpers.py:351-399` 的 6 个魔法长度阈值提为 `DEFAULT_CONFIG` 里的具名配置（如 `compression_thresholds`），注释说明它们是字符数代理；
4. 配置：`TradingAgentsGraph.__init__` 改为 `self.config = {**DEFAULT_CONFIG, **(config or {})}` 深合并，消灭部分配置 KeyError 陷阱；`dataflows/config.py` 的 368 行作文删到只剩 40 行代码。

**验收**：传部分配置 `{"max_debate_rounds": 5}` 构造图不再崩；新增一个状态字段时只需要动一处（写进结构化块）。

### Phase 4：数据层（放在有真实需求时再做，别提前）

方向（细节直接看 `REFACTORING_ROADMAP.md` Phase 3，仍然有效）：

1. 先建 `MarketDataPort` 协议（按能力组织：行情/快照/概念/资金流……），`cn_indicators` 改走端口，消灭 `dataflows → screener` 反向依赖；
2. `ScreenerDataAccess` 拆之前先拆依赖方向，否则只是"把屎分装进小盒子"；
3. 四模块环随端口建立自然消解；
4. 供应商命名与现实对齐：要么承认全是 akshare 薄包装并改名，要么真的按源拆 adapter。

### 明确不要做的事

- 不要在 Phase 0-3 完成前加任何新功能——每个新功能都会同时落在双写状态、三驱动器、双 CLI 上，成本×3；
- 不要推倒重写；不要一次性移动全部文件；不要引入 DI 容器/事件总线/规则引擎这类"高级"抽象；
- 不要把业务判断搬进 Prompt 来躲 Python 逻辑；
- 不要把 `tests/`、报告产物、缓存提交进仓库（.gitignore 已基本覆盖，删 `-no` 后再核对一遍）。

## 最后：给 vibe coding 时代的三条自保规则

1. **AI 改完代码，先 grep 引用再信**。这次发现的 `aggressive_debator.py`、死函数、假 alias 逻辑，全是"看起来在干活、实际没接线"的代码；
2. **复制文件是负债**。下次想让 AI"把 X 搬到新位置"，正确指令是"搬走并让旧路径薄转发"，而不是"复制一份过去改"；
3. **except Exception 是止痛药不是治疗**。每写一个，先问：这个失败是"供应商挂了"（可以降级）还是"我代码错了"（必须炸）。
