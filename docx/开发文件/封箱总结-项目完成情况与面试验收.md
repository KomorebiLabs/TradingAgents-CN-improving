# TradingAgents-CN 封箱总结：项目完成情况与面试验收

> 记录日期：2026-08-25  
> 封箱基线：`fork/main`，合并 PR #28 后的提交 `9e55dd7`  
> 目标：把 GLM 5.3 的原始交付、后续接力修复、真实运行证据和剩余边界集中记录，作为面试复盘与后续维护入口。

## 一、封箱结论

项目目前可以作为“面试可展示的 A 股多智能体研究决策辅助系统”封箱，不能包装成生产级自动交易系统，也不能宣称模型已经经过真实正确率评测。

当前已经形成两条可解释的业务链：

1. **Analyzer 主 LangGraph 链**：分析师 → 多空研究辩论 → Research Manager → Trader → 风控辩论 → Portfolio Manager；
2. **Screener 链**：股票池 → 数据供应商降级 → Technical / SmartMoney / Policy 三策略 → Merger → 证据资格门禁 → 可选 DeepAnalyzer。

封箱时最重要的判断不是“有没有候选股”，而是系统能否在数据不足时拒绝伪造推荐。真实 Screener 运行中候选可以被保留为 research candidate，但在证据资格不足时 `recommendation_eligible=false`，这条边界应作为项目的核心设计亮点。

## 二、GLM 5.3 原始工作

以下内容依据开发计划、GLM 完成情况审查报告、历史提交和当前源码交叉整理。这里区分“代码骨架/离线实现”和“真实业务验收”，不把 GLM 的局部测试绿灯直接等价为全链路完成。

### 2.1 Agent 工程主线

- 建立收敛驱动的研究/风险辩论逻辑，加入上下文预算、截断保护和阶段路由；
- 建立 A4 数字证据校验基础，包括数值抽取、单位、语义和范围检查；
- 建立 A3 上下文仪表化与阈值校准基础；
- 实现 HumanGate 节点、`interrupt()` / `Command(resume=...)` 的图级基础；
- 建立 Prompt 注入防御的宪法提示、定界符、过滤和审计设计；
- 引入 checkpoint、run-id、分类重试和部分异常可观测能力；
- 补充 B2 PIT 时间语义、B3 组合上下文、B5 A 股执行规则的第一版实现；
- 完成与这些能力配套的单元、契约、图拓扑和状态迁移测试。

### 2.2 既有工程治理成果

- LangGraph 图、AgentState、Application Contract、Execution Events 和 Harness 形成分层边界；
- 多入口、状态双写、工具路由和供应商访问逐步收口；
- Screener 的 Merger、数据访问、策略和报告模块完成拆分；
- 回测、敏感性、消融和评测框架落地，并明确区分 `framework_ready` 与 `real_model_run`；
- CI、README、架构说明、面试导航和治理报告形成作品化基础。

### 2.3 GLM 交付中被审查发现的缺口

Codex 接力审查确认，GLM 当时不能直接宣称“计划全部完成”。典型问题包括：

- CLI 的 `resume_payload` 未贯通到应用服务，HumanGate 真实恢复会触发 `TypeError`；
- Alpha Vantage 日期异常路径引用未定义 `logger`；
- RAG 直返路径绕过统一注入过滤；
- B3/B5 主要停留在 Prompt 软约束，缺少程序化硬校验；
- A4 缺少完整 `as_of` 语义和 `verified/derived/unverified` 闭环；
- 真实长链路、真实 kill/resume、真实 HITL 暂停/恢复没有充分证据。

这些缺口已经写入 [GLM 完成情况审查报告](审查报告-8-AI-Agent工程深化一周计划-GLM完成情况.md)，不是事后抹平历史，而是保留真实接力依据。

## 三、Codex 接力修复与扩展

### 3.1 主 LangGraph 接力修复

- 打通 `AnalysisService → TradingAgentsGraph → Command(resume=...)` 的 HumanGate 恢复参数；
- 为 abort 生成 `abandoned.json`，并补充安全审计和运行结束产物；
- 统一 RAG 直返与普通工具路由的定界、过滤和 run-scoped salt；
- 修复 Alpha Vantage 日期格式异常路径；
- 增加连接/超时 jitter、429 的 `Retry-After` 处理和 403 克制策略；
- 实现 B3 组合约束硬校验，以及 B5 的 T+1、涨跌停、锚定价和成本提示；
- 增加 A4 的 `verified/derived/unverified` 三态与 B2 的时间门禁；
- 修复默认配置读取，使真实运行可以按用户环境使用 Agnes，而不会静默落到 OpenAI。

### 3.2 真实 Analyzer / DeepAnalyzer 证据

- 使用 Agnes-only 配置完成一次 Analyzer headless 真实运行：`agnes-2.5-flash`，最终 `HOLD / CAUTIOUS ACCUMULATE`，26 次 LLM 调用、37 次工具调用，约 9 分 37 秒，报告和审计产物落盘；
- 修复 LangChain usage 位于 `message.usage_metadata` 导致成本统计为 0 的问题，并用最小真实 Agnes 请求验证 `input_tokens=289`、`output_tokens=17` 的回调统计；
- 使用固定、可审计的合法候选夹具完成 DeepAnalyzer Agnes 真实验收：`GRAPH_COMPLETED`、`success=true`、`fallback_used=false`；
- 明确说明 DeepAnalyzer 夹具是执行合同验收，不是当天真实选股结果，不能被包装成策略准确率。

### 3.3 数据供应商与证据链

- 处理新闻空结果、财务三表 unavailable 和 `0/5` 工具证据验证问题，建立可见的降级提示；
- 接入 CNINFO 官方公告源适配器；
- 接入可选 Tushare Pro 财务适配器；当前因用户账号权限/积分限制，`TUSHARE_ENABLED=false`，不得宣称 Tushare 已提供默认财务数据；
- 保留 AkShare、yfinance、BaoStock 等后备链，并区分“供应商返回数据”和“报告数字已被安全验证”；
- 统一主链和 Screener 的供应商健康状态，记录状态、调用次数、失败率、平均延迟、P95、样本数和脱敏错误；
- 增加供应商接口字段归一化、三次连续失败短路和空股票池缓存拒绝；
- 增加 UTF-8 产物编码损坏标记检测，避免乱码继续污染 JSON/Markdown。

### 3.4 Screener 六批次收口

- 修复 Stage A / Stage B 输入预算、策略停滞、合法零候选和市场规则问题；
- 修复回测延迟成交、T/T+1 执行时序、样本外窗口和前视偏差风险；
- 提高 Merger 推荐质量，校准 SmartMoney / Policy 标签，区分评分、置信度和推荐资格；
- 修复名称解析、指数成分降级、yfinance A 股代码格式和 VWMA 成交量输入；
- 实现 FOCUSED → MVP → FULL 阶梯真实运行；
- 新增 Screener acceptance monitor，按 `completed_at` 选择每日最新 run，拒绝通过重复日期伪造连续验收。

## 六、封箱时仍需诚实保留的边界

以下项目不能在面试中说成已经完成：

1. 没有真实模型正确性评测统计，`eval` / `ablation` 框架就绪不等于产生了业务结论；
2. 没有完成连续 5 个不同交易日的 Screener 稳定性验收；
3. 没有完成最新代码下真实 HITL 暂停、comment、resume 和 abort 的完整交互证据；
4. Tushare 适配器已接入，但当前关闭，账号权限不足时由后备源承担数据；
5. 免费数据源仍可能接口漂移、限流或返回空数据，系统能做的是把失败显式化并降级，不是保证供应商永不故障；
6. 回测收益、Screener 候选和 Agnes 单次决策都不是投资收益承诺；
7. 项目没有实盘下单、自动交易、日内高频或风险免责能力。

## 七、面试推荐口径

推荐定位：**A 股多智能体研究决策辅助系统，具备 Screener 候选发现、LangGraph 多阶段分析、供应商降级、证据资格门禁和运行可观测性。**

推荐强调三件事：

- 我把 Agent 从 Prompt 串联升级成有状态、可恢复、可观测的工作流；
- 我把“数据缺失时不能推荐”做成程序门禁，而不是只在 Prompt 里提醒模型；
- 我能区分代码实现、离线证据、真实运行证据和业务效果，绝不把一次运行包装成准确率。

建议使用 `v0.9.0-interview-ready` 作为面试展示标签，不建议使用 `v1.0.0` 或 `production`，因为多日稳定性、真实评测和 HITL 长链路仍未封闭。
