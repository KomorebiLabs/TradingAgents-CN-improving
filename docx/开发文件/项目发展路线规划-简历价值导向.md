# 项目发展路线规划 —— 面向简历价值的升级路径

> 作者：ZCode（重构系列收尾后撰写）｜日期：2026-08
> 目标：让 TradingAgents-CN-improving 从"结构健康但业务未验证的 demo 级工程"，升级为**能在简历上立住、有可量化交付物、有完整故事线**的作品。
> 本文基于《屎山报告 1-5》《交接文档》与重构收尾时的整体评估。

---

## 一、现状判断（一句话）

**这是一个"工程治理奇迹、业务验证缺位"的项目**：架构分层、测试护栏、等价性验证达到了罕见水准；但作为一个交易系统，**决策有效性零证据、数据命悬免费爬虫**。这两点正是"demo 感"的来源。

## 二、什么能让它"上简历"？（检验标准）

简历上出色的项目，靠的不是"更炫的功能"，而是四个**可被检验**的信号：

| 信号 | demo/玩具 | 简历级 |
|---|---|---|
| **可量化成果** | "我搭了个多智能体框架" | "回测夏普 1.2 / 胜率 58% / 最大回撤 -18%" |
| **闭环可验证** | 只有单元测试 | 有真实数据 + 真实模型跑通 + 绩效报告 |
| **复杂度展示** | 一条线性流程 | 多智能体辩论 + 语义路由 + 事件协议 + 可观测性 |
| **可信可复现** | clone 后跑不起来 | 一键起 + 架构图 + 演示 + 复盘文档 |

本报告所有路线都对齐这四条标准。

---

## 三、核心路线（按"简历命中率"排序）

### R1 · 回测与信号有效性闭环 —— 第一弹药 ⭐⭐⭐⭐⭐

**做什么**：接入 Backtrader（Phase 7 落地），把 Screener 输出 → 历史信号 → 持仓/资金曲线 → 绩效报告（夏普、最大回撤、胜率、对沪深300 超额收益）一条龙打通；选 2019–2025 多个市场环境切片回测。

**为什么是简历第一**：
- 把"我做了个选股系统"变成"**我做了个可回溯验证的选股系统**"——这是 demo 与作品的分水岭；
- 面试 90% 的追问会落在"你怎么知道它有效？"——回测是目前唯一能给出答案的手段。

**简历叙事**：《基于多智能体与语义路由的 A 股选股框架，内置 Backtrader 回测引擎，2019–2025 切片验证，输出夏普/回撤/超额收益》

**工作量**：中等（1-2 周）。**风险**：结果可能不理想——但那并不毁简历，**"诚实评估 + 告诉你它在哪些市况有效"本身就是加分项**，比回避验证强百倍。

### R2 · ~~可视化 Web 面板 + 服务化~~（已按需删除 ✂️ 2026-08）

> 用户因 24 小时时间约束确认不做。其底层铺垫（`application/events` 事件协议 + `AnalysisService` 服务化接缝）**保留在仓库**，未来如需可低成本加回——删除的是"本轮路线项"，不是架构基础。

### R3 · 数据可靠性工程化 —— 把隐忧变优点 ⭐⭐⭐⭐

**做什么**：
- vendors 层类型化（60+ 处 `except: return None` → `raise VendorUnavailable/DataNotFound`，只随真实 bug 逐链路推进）；
- 数据健康度监控：供应商失败率、降级链审计、探测结果落日志/计数；
- 缓存策略文档化（现有 `_hist_cache`/探测缓存已具备，补 TTL 与失效指标）。

**为什么**：简历写"**我设计了类型化错误体系与供应商健康监控**"直接体现工程成熟度；且这是隐藏最深的真实缺陷（数据坏了静默返回空），修复它就是**真实的 reliability 案例**。

### R4 · 消融与对比实验 —— 证明"多智能体"不是噱头 ⭐⭐⭐⭐

**做什么**：用同一批历史 ticker 跑对照：
- 单 agent（无辩论） vs 全量多智能体；
- 辩论开/关；
- 语义路由（conflict resolver / 路由决策）开/关；
- 输出：决策质量、覆盖度、稳定性（对同一输入重复 N 次的一致性）。

**为什么**：这是从"架构好看"到"**架构有效**"的证据升级——论文/面试级的 claim（"消融实验证明辩论机制降低决策方差"）。免费且极高 ROI，因为构建已就绪，只差实验外壳。

**简历叙事**：《通过消融实验量化多智能体辩论与语义路由对决策质量的影响》

### R5 · 工程收尾（完成态）—— 让洁癖闭环 ⭐⭐⭐

**做什么**：`cli` 顶层包迁入 `tradingagents.cli`（消除撞名）、config 全局单例收口、状态 v2.1（节点停写平铺字段）、改名化石（`_generate_llm_route_insight`）、版本单一来源核查。

**为什么**：这些是"深水区细节"，面试官随机深挖时不露怯；且都是小步、低风险、别处已在路线图上的活。

### R6 · 作品化：文档 × 演示 × 复盘文章 ⭐⭐⭐⭐⭐（配合前几项做）

**做什么**：
- 架构图（系统分层图 + 决策流程图，ASCII/Excalidraw/png）；
- README 升级为"技术叙事"：问题 → 解法 → 收益 → 架构 → 运行 → 回测结果；
- 录一段"实时分析流"演示（gif/视频）；
- 把屎山报告 + 重构方法论整理成**公开复盘文章**（工程博客 / GitHub 讨论）。

**为什么**：简历上放链接，面试官 80% 先看 README 和截图；**"有公开复盘"是最强的影响力信号**（说明你不仅会写码，还会表达工程判断）。

### R7 · 一键可复现 —— 挽回可信度 ⭐⭐⭐⭐

**做什么**：真实链路 smoke（真实 API + 真实 LLM 跑单一标准流程）、`.env.example` 完善、干净版 Docker（当前 docker-compose 被清洗标记过，重做一个真正可用的）、`make demo` 脚本。

**为什么**：demo/玩具项目的死穴是**别人 clone 后跑不起来**；"5 分钟可复现"是把可信度焊死的一步。

---

### R8 · 可信度修复：模型目录与命名祛魅（新增）⭐⭐⭐⭐

**做什么**：把 `default_config` / 文档里的虚构或超前模型（GPT-5.4 / Gemini 3.5 Pro / Claude 4.8 等）改为**真实可用**的模型名（或明确标注 placeholder）；统一模型目录；README 不再写不存在的型号。

**为什么**：这是评估中明确指出、却最容易被忽略的**可信度雷区**——读者/面试官一旦发现模型名对不上真实生态，整个项目的专业性会瞬间折损。零成本、高收益的"防雷"。

**简历价值**：把"虚假繁荣"换成"诚实精确"，反而展示工程判断力。

### R9 · 评分参数校准与敏感性分析（新增）⭐⭐⭐⭐

**做什么**：在 R1 回测框架上，对关键权重/阈值（merger 冲突规则、`heat_gap≥28`、`spread≤6`、各策略权重）做**敏感性分析**：逐参数扰动 ±10~20%，量化绩效指标对每个参数的敏感度；对高敏感参数做简单网格调优并记录依据。

**为什么**：直接把"感觉合理"的魔法数字变成"有敏感性证据"的参数——即便不调优，敏感性分析本身就是专业性的证明。

**简历价值**：《参数敏感性分析与阈值校准》——工程 × 研究的交叉亮点。

### R10 · 决策正确性评测集（golden cases）（新增）⭐⭐⭐⭐

**做什么**：手工构建 20-30 个"已知结局"的 A 股案例（如某股后续 20 日 +25% / −15%），跑完整分析链，对比系统决策 vs 真实结局，输出**准确率/混淆矩阵**；并作为持续回归评测集（不只是 characterization 冻结，而是对"正确性"的抽查）。

**为什么**：这是对"360 测试保证不回归但不保证正确"的直接回应——给 LLM 决策链路一个**可复现的正确性评估基线**。

**简历价值**：带"决策准确率"数字的评估集，比纯单元测试更贴"系统做对没有"。

### R11 · LLM 成本与输出结构化（新增）⭐⭐⭐⭐

**做什么**：结构化输出（对 `<decision>`/`<investment_plan>` 用约束生成或后置解析，已有 confidence 解析先例）、LLM 调用缓存、按标的复杂度分级的分析深度（简单标的跳过部分辩论）。

**为什么**：成本与耗时是可量化指标（token/次、秒/次），且让"演示跑一次"成本可控——简历演示同样受益。

**简历价值**：成本优化数字（如 −30% token/次）+ 结构化输出健壮性。

## 三(补) · 劣势覆盖自检表（本轮修订后）

| 评估中列出的劣势 | 覆盖路线 | 状态 |
|---|---|---|
| 决策有效性零证据（无回测） | R1 回测闭环 | ✅ |
| 评分公式手调权重 / 魔法阈值 | R9 参数校准+敏感性分析 | ✅ **本次补** |
| 数据命悬爬虫 + vendors 静默 `None` | R3 数据可靠性+类型化 | ✅ |
| 安全网≠正确性（无 golden 真值） | R10 决策正确性评测集 | ✅ **本次补** |
| LLM 成本与输出不稳定 | R11 成本+结构化输出 | ✅ **本次补** |
| 单机单用户（无服务化） | R2 已按需砍掉 | ➖ 按取舍接受现状 |
| 残留技术债（vendors/cli/config/化石） | R5 工程收尾 + R3 | ✅ |
| 文档/模型名存疑（GPT-5.4…） | R8 可信度祛魅 | ✅ **本次补** |

**并入分期**（维持 A-D 骨架）：
- Phase A：R1 回测 + **R8 可信度（低成本先修）** + R6 作品化
- Phase B：**R9 灵敏度分析** + R4 消融
- Phase C：R3 + **R10 正确性评测集**
- Phase D：R5 + **R11 成本/结构化** + R7 一键复现

## 四、24 小时冲刺计划（用户时间约束 · 2026-08 重排）

> 原则：**只做三件事**——①给系统一个"可验证"的证明（回测）②让仓库"看起来专业"（作品化+祛魅）③让别人"跑得起来"（一键复现+真实 smoke）。
> 砍掉所有需要多轮真实 LLM 运行 / 长期迭代的项（R2 已删；R4/R10/R5/R9 完整版、R3 大工程不在 24h 内）。

```
[ 0-10h] R1·迷你回测闭环 ───────── 核心，简历第一弹药
         目标：不是完整回测平台，而是"能跑出真实资金曲线 + 绩效数字"的最小闭环
         Screener 历史窗口筛选(3-6个月) → 候选信号 → Backtrader 简单策略
         (等权买入前N/持有M日) → 绩效报告(总收益/夏普/最大回撤/对比沪深300)
         → 一张图 + 一段 markdown
         风险预案：免费数据拉取/格式坑；结果平庸 → 如实呈现 + 强调评估方法论

[10-13h] R6·作品化（README 技术叙事 + 架构图 + 回测结果页）
         README：问题→解法→架构→回测结果→快速开始（含真实模型名）
         架构图：分层图 + 决策流程图（png/ASCII）

[13-15h] R8·可信度祛魅（模型名修正 + 配置核查）── 低成本防雷

[15-17h] R7·一键复现（start 脚本 + .env.example 完善 + clone 验证）

[17-19h] 真实链路 smoke：真实 LLM 跑 1 只股票，验证全链路 + 截图素材

[19-24h] 缓冲（数据/依赖坑）+ 演示素材（gif/截图）+ 复盘文章骨架
         + 提交推送（PR 合并留痕）
```

**排序理由**：
1. **R1 是唯一能在 24h 内产出"简历硬数字"（夏普/胜率/回撤）的项**，其余都是"好看/可信"，只有它能回答"你怎么知道有效"；
2. R6 决定面试官点开仓库的第一印象；R8 防雷；R7+smoke 决定"能不能当场跑起来"；
3. 最后 5h 缓冲不是浪费——免费数据 API 和依赖坑是 24h 开发的确定性开销。

**超时降级预案**：保 R1 迷你版 + R8 + README；砍 R7 与复盘文章。

**冲刺后**（时间允许再补）：R4 消融 / R9 敏感性 / R10 评测集 / R3 类型化，均按上文路线推进。

---

## 五、诚实边界（规划的前提）

1. **回测不是免责**：A 股负和博弈 + 免费数据，回测结果可能平庸；但"诚实的回测 + 复盘方法论"比"不敢验证"高级得多——这条路线的前提是接受真实结果。
2. **不要堆"更炫但更空"的功能**：每条路线都绑定一个**可量化交付物**，避免 demo 化。
3. **时间投入**：A~D 全做约 2-3 个月断续；若只做 A+B 已足以让简历质变。
4. **LLM 成本**：R1/R4 涉及批量历史回测/评测，注意控量（用 quick 模型 + 抽样）。

---

## 六、结论

这个项目最稀缺的资产是**工程治理本身**（测试护栏、分层、等价性验证、文档接力）——这些已经远超大部分简历项目。缺的只是**三样东西**：
**① 可验证的绩效闭环（回测）② 可演示的服务化界面（Web）③ 公开的作品化表达（文档+演示+复盘）**。

补齐这三样，简历上的它就不再是"一个多智能体 demo"，而是：
> **"面向 A 股的多智能体选股框架：LangGraph 状态机 + 语义路由 + 结构化记忆 + 事件流服务层 + 回测验证闭环，360 离线测试，B 组六大千行文件拆解重构"** —— 工程深度、完整度、可信度三线齐备。

**最优先一击**：从 R1（回测）开始——它既是简历第一弹药，也是全项目当前唯一缺失的"专业级"证明。
