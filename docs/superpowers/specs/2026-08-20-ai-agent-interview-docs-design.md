# AI Agent 面试作品化文档设计

- 日期：2026-08-20
- 状态：设计已获用户确认，待实施计划
- 目标岗位：AI Agent / LLM 工程
- 关联范围：`README.md`、`docs/architecture.md`、`docs/interview-notes.md`

## 1. 目标

在不修改业务代码、不运行真实 LLM API 的前提下，将项目已有的 LangGraph、多智能体、工具路由、状态契约、可观测性、评测护栏和重构成果，整理成面向 AI Agent / LLM 工程面试的三层材料：

1. README 第一屏提供简洁入口；
2. `docs/architecture.md` 提供架构和实现证据；
3. `docs/interview-notes.md` 提供可直接复述的项目介绍和技术问答。

文档必须诚实区分“已验证”“已实现但仅离线验证”“待验证”和“限制”。

## 2. 叙事主线

项目的核心卖点不是 Agent 数量，而是把一个具有多入口、多状态形状、多数据供应商和历史遗留代码的系统，逐步治理成可验证、可观察、可扩展的 Agent 平台。

重构故事按以下因果链展开：

```text
表面问题：大文件、重复入口、异常很多
    ↓
根因：状态双写、三套图驱动、CLI 分叉、静默 fallback、
      数据层反向依赖、配置双中心、异常边界模糊
    ↓
入口收口：移除静默 ImportError fallback，统一 CLI 和版本来源
    ↓
执行收口：统一 LangGraph 流式驱动，UI 不再触碰图内部
    ↓
契约收口：AgentState canonical schema + schema_version
    ↓
数据层治理：MarketDataPort、依赖环消解、类型化供应商错误
    ↓
按变化原因拆分 1905 行 ScreenerDataAccess
    ↓
使用离线 contract / golden / parity 测试验证行为不漂移
```

面试表达应使用“增量收口、行为保持、边界治理”，避免使用“全部重写”或夸张的“彻底解决所有问题”。

## 4. 证据分层

文档统一使用以下标签：

- **✅ 已验证**：当前仓库测试、源码或 `reports/` 产物有依据；
- **🧱 已实现 / 离线验证**：代码路径和离线护栏存在，但没有真实 API 运行证据；
- **🧭 待验证**：治理报告提出但本轮不执行；
- **⚠️ 限制**：数据窗口、交易成本、存续偏差、供应商漂移等边界。

以下内容不得写成已验证结果：

- 真实 API 端到端分析；
- 消融实验结论；
- 正确性评测结果；
- 多窗口回测；
- 计入交易成本后的收益；
- LLM 决策预测能力。

回测 `82.86%`、夏普 `2.17`、超额 `+56.57%` 只能作为单窗口、技术因子、未计成本且存在存续偏差条件下的工程实验结果。

## 5. 重构案例的事实边界

历史“屎山清理”文档作为重构过程材料使用，报告 1/2 的数字视为历史诊断基线，报告 4/5 和交接报告中的后续数字视为施工记录或当前治理边界；不能把历史基线的“0 测试”“171 处异常”等内容直接写成当前状态。

可以稳定使用的案例：

- 静默 ImportError fallback 被移除；
- 安装入口和版本来源统一；
- `stream_analysis()` 统一图执行路径；
- AgentState 结构化块确立为 canonical，并引入 schema version；
- `MarketDataPort` 打断数据层反向依赖；
- 依赖环被测试保护；
- `ScreenerDataAccess` 从 1905 行门面拆成按变化原因组织的模块；
- 公开方法、返回值和 fallback 顺序保持；
- 测试从重构阶段逐步增加，并持续使用离线护栏。

## 6. 明确不在本次范围内

- 不运行真实 API 或 LLM；
- 不修改业务逻辑；
- 不修改供应商实现；
- 不执行 point-in-time 审计；
- 不扩展回测；
- 不修改或删除已有文件；
- 不整理用户已有的删除和未跟踪文件；
- 不提交 Git commit，除非用户另行明确要求。

## 7. 验收标准

1. README 只做增量修改，并保留现有未提交内容；
2. 两个新文档中的代码路径和符号名称与当前仓库一致；
3. Mermaid 图有文本降级版；
4. 每一个数字都有来源或限制说明；
5. 未运行的 API、消融、评测和多窗口回测不被描述为已验证；
6. 文档能支持 AI Agent / LLM 工程面试中的架构、状态、工具、观测、评测和重构追问；
7. 文档完成后只做静态一致性检查和必要的 Markdown 检查，不进行真实网络调用。
